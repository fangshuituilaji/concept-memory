## 1. 已确认的目标与硬约束

- 在现有 Python、Markdown 基础上，完整纳入 TypeScript/TSX、JavaScript/JSX、Java、Go、Rust、C/C++、C#；按阶段实现，但缺少任一语言不能宣告整体完成。
- “支持”指文件发现、主要结构识别、概念生成、模型检索、准确取卡贯通；不包括编译器级类型推导、宏展开、跨语言调用分析。
- **概念名称、定义、背景继续由 qwen-flash 生成。解析器只提供源码事实，不把每个符号直接变成概念。**
- **query 检索继续由 qwen-flash 阅读全部概念目录后选卡排序；保留大目录分批与终排，不增加关键词、向量或语言过滤的前置召回。**
- 模型生成失败，按有界重试规则明确报错；禁止本地兜底概念。模型检索失败继续明确报错，禁止离线替代。
- 保留扫描等待、query 瘦身目录、card_ids 完整卡片，以及真实共同取卡才增加跨文件使用连线的机制。
- 本轮交付此计划，不实现功能、不修改宿主配置、不发布。执行本计划时默认完成源码、测试和本地候选包；公开发布另行确认。

## 3. 首版支持矩阵与边界

| 语言 | 默认扩展名 | 必须覆盖的结构 |
| --- | --- | --- |
| Python / Markdown | `.py / .md` | 保持现有 AST、标题锚点及围栏内伪标题排除行为。 |
| TypeScript | `.ts .mts .cts`，包含 `.d.ts/.d.mts/.d.cts` | 函数、类、方法、命名箭头函数、interface、type、enum、namespace、声明与重载。 |
| TSX | `.tsx` | 上述适用结构及含 JSX 的函数/箭头组件，使用独立 TSX grammar。 |
| JavaScript / JSX | `.js .mjs .cjs .jsx` | 函数、类、方法、命名函数表达式/箭头函数、导出与 CommonJS 赋值函数。 |
| Java | `.java` | package 作用域、类/interface/enum/record、构造器、方法与重载。 |
| Go | `.go` | 函数、带接收者方法、struct/interface、命名类型；方法归入接收者类型。 |
| Rust | `.rs` | fn、struct/enum/trait/type/mod、impl 方法；区分不同 impl/trait 中的同名项。 |
| C | `.c .h` | 函数定义/声明、struct/union/enum、typedef；不展开预处理宏。 |
| C++ | `.cpp .cc .cxx .hpp .hh .hxx .C .H`，兼容 `.h` | namespace、class/struct、构造/析构、成员/自由函数、模板及类外方法定义。 |
| C# | `.cs` | namespace、class/interface/struct/record/enum、构造器、方法、属性及表达式体成员。 |

- `.h` 分别用 C/C++ grammar 解析，选 ERROR/MISSING 较少者；平局且 C++ tree 出现 namespace/class/template/using 等 C++ 独有节点时选 C++，否则选 C。两者均有错误则明确失败，不猜测已完整支持。
- 先匹配 `.C/.H` 特例，再对其他扩展名大小写归一；声明文件按最长已知后缀识别，不能被当作普通文件忽略。
- 匿名函数和默认匿名导出使用稳定文件内锚点，如 `default@L12`，不虚构用户命名；无显式符号但非空的合法源码仍交给模型归纳文件级概念。
- 首版不包括 Vue/Svelte 单文件组件、HTML/CSS/JSON/YAML、Kotlin/Swift/PHP/Ruby，以及 Rust 宏展开、C/C++ 编译配置还原。
- 保留已有忽略目录；新增 `.concept-memory`、`.next`、`.nuxt`、`coverage`、`target`、`obj`，排除 `.min.js` 与 `.min.mjs`。源码测试目录和类型声明仍扫描；不一概忽略 `bin`、`vendor`。
- 暂不新增 .gitignore 解释器、通用插件框架或自定义语言配置 UI。新增忽略规则必须有“不误排普通源码”的反例。

## 4. 最小架构与检验器

固定数据流：文件发现 → 语言识别/解析 → SourceFacts → qwen-flash → ConceptDraft → 本地证据锚定 → 原存储 → qwen-flash 检索 → 原取卡接口。

- 新建 `src/memory_system/languages.py`：唯一语言/扩展名注册表，保存 language_id、后缀、围栏标签、grammar 加载入口及解析版本。
- 新建 `src/memory_system/parsers/`：公共 Tree-sitter 基础代码与逐语言适配文件。保留 `TreeSitterSourceAnalyzer` 作为兼容入口，Python/MD 继续走原路径。
- 复用 `SymbolFact`、`SourceFacts`、ConceptDraft、ConceptCard；需要新增字段时使用向后兼容的默认值，不重做存储或 MCP 工具签名。
- grammar 按需加载并缓存 Language；Parser 不跨并发任务共享。语法依赖缺失/ABI 不匹配必须给出语言和修复位置，不回退正则或符号名概念。
- 本地解析器以 UTF-8 字节解析、以 1 起始且两端包含的行号返回；符号排序固定，注释里的假函数不能生成符号。
- 每语言至少一个正常样例、一个该语言特有结构、一个 Unicode/CRLF 或同名边界；断言名称、类型、作用域、精确行号和实际源码，不只断言“有卡片”。
- 可重复单测用固定模型响应代替网络；至少一层在 DashScope 调用边界替身以验证真实生产合成/检索代码确实被调用。替身不能进入产品运行路径。
- 最终须有真实 qwen-flash 生成与检索记录、混合语言项目取卡记录、本地候选包自检。模拟通过不等于在线验收通过。

## 5. 执行纪律

以下任务按编号串行推进。每个任务先写一个行为测试并运行，记录预期的 RED；再做最小实现得到 GREEN；最后仅在绿色状态下整理代码。环境故障、缺依赖和收集错误不算行为 RED。
每次只完成一个小检查点；失败先定位当前点，不趁机改检索算法或重写全库。每完成一步更新 `docs/verification/multilang/执行记录.md`，记录用例、命令、RED/GREEN 结果、改动文件和未解决项；不得编造测试次数。
任务表中的“新建”文件均为拟议路径，不代表已存在。内部检查点由执行 agent 自动核验，不每步向用户要批准；仅需求取舍、无法满足约束、真实项目缺失或对外发布时提问。
