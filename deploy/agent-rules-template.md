# 代码定位规则模板（写进用户项目的 AGENTS.md）

这份模板的读者是**安装方 AI agent**。目的：让用户项目里的 coding agent 在定位代码时
优先调用 concept memory，而不是直接 grep / 整文件读。

用法：把下面「规则正文」整段追加到用户项目的 `AGENTS.md`（没有该文件就新建）。如果用户
项目已有 `AGENTS.md`，**只追加，不要覆盖或重写用户原有内容**。

---

## 规则正文（从这里开始，整段复制到目标项目 AGENTS.md 末尾）

## 代码定位规则（concept memory）

- 需要定位、理解本工作区的代码时，**禁止直接 Grep/ripgrep 或整文件 Read**。

- 每次会话开始先调用 `scan_codebase` 建立该目录的概念索引；检索结果为空或连续报错时，也先重扫再检索。

- 索引就绪后一律先调用 `search_concepts` 传 query（自然语言概念或关键词，中文即可，如「使用边」「重试逻辑」）；
  它返回瘦身目录（card_id、概念名、文件行号、一行定义预览，不含源码摘录）。检索连续报错说明在线重排不可用或索引未就绪，重扫后仍失败才可回退 Grep/Read。

- 从返回结果中挑出需要的卡片，再次调用 `search_concepts` 传 `card_ids`（一次可传多张）阅读完整卡片（含按行号截取的源码摘录）。

- 只有当卡片摘录没有覆盖你需要的少数几行时，才用 Read 按行号区间补读；仍找不到线索才回退到 Grep。

- 每次多卡片取卡都在为概念网络累积真实使用连线，检索会越用越准。

## 规则正文结束
